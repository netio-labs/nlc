# 拓扑编辑器

拓扑编辑器用于创建和修改 Lab 拓扑。在 Labs 页面点击 **新建**（Create），或点击已有 Lab 旁的 **编辑**（Edit）即可打开。

## 布局

| 区域           | 说明                                                    |
| -------------- | ------------------------------------------------------- |
| **顶栏**       | Lab 名称、描述、查看按钮（已保存的 Lab）、保存 Lab 按钮 |
| **左侧边栏**   | 构建面板（节点/链路属性）和 Lab 设置                    |
| **画布**       | ReactFlow 画布——拖动、缩放和连接节点                    |
| **设备工具栏** | 位于画布底部居中的浮动工具栏                            |

## 添加节点

点击画布底部设备工具栏中的图标：

- **Router 图标**——添加 IOU Router 节点
- **Switch 图标**——添加 IOU Switch 节点
- **Virtual PC 图标**——添加一个轻量级测试主机（参见[节点类型](#节点类型)）
- **IOULive86 图标**——添加一个连接到服务器物理接口的桥接（参见[节点类型](#节点类型)）
- **Container 图标**——添加一个 Podman 容器节点（参见[节点类型](#节点类型)）

每个新节点放到画布上时会自动生成名称（`r1`、`r2`、`s1`、`vpc1`、`lan1`、`c1`……）。IOU 节点和容器节点使用该 Profile 的第一个可用镜像；对于 IOU，如果尚未上传任何镜像，镜像字段为空，必须先设置才能运行 Lab。Virtual PC 和 IOULive86 节点使用固定的内置镜像，无需上传。

## 节点类型

| 工具栏图标 | Profile     | 接口                | 说明                                                                      |
| ---------- | ----------- | ------------------- | ------------------------------------------------------------------------- |
| Router     | `iouRouter` | Ethernet + Serial   | Cisco IOU 路由器镜像（`I86BI_LINUX-*`）。                                 |
| Switch     | `iouSwitch` | Ethernet            | Cisco IOU L2 镜像（`I86BI_LINUX_L2-*`）。                                 |
| Virtual PC | `vpc`       | 一个端口（`eth0`）  | 轻量级纯用户态测试主机。                                                  |
| IOULive86  | `ioulive86` | Ethernet            | 将 `e0/0` 桥接到服务器物理网卡，或（`auto` 模式）桥接到 `e0/1` 上的容器。 |
| Container  | `container` | 1–16 个 Ethernet 端口 | 一个 Podman 容器（以 root 运行）。                                        |

### Virtual PC

Virtual PC 是一个小型终端设备，用于在 Lab 内部测试连通性，开销远小于完整的 IOU/IOL 节点。像其他节点一样通过控制台登录，使用其简单的命令集：用 `ip address 10.1.1.10/24`（或 `ip address dhcp`）设置地址，用 `ip gateway 10.1.1.1` 设置默认网关，然后可使用 `ping`、`telnet`、`ssh`（显示服务器的版本和算法）、`get`（HTTP）以及 `web start`（一个小型 HTTP 服务器）。其配置可用 `save` 保存。

其镜像固定为 `NETIO_VIRTUAL_PC`，并且始终只有一个 Ethernet 端口。

### IOULive86 桥接

IOULive86 Bridge 将一个 IOU/IOL 接口连接到**服务器上的物理网卡**。

选中 IOULive86 节点时，**构建**（Build）标签页会额外显示 **绑定接口**（Bind interface）字段，即该节点桥接到的服务器物理接口。或者也可以选择 `auto` 以桥接容器：在 `auto` 模式下，节点会多出第二个端口 `e0/1`，用于容器链路。

桥接需要在服务器端进行一次性设置（为桥接程序配置免密 `sudo`）——参见[安装指南](./07-installation.md#5-ioulive86-物理网络桥接)。

IOULive86 控制台不提供设备 CLI，它显示实时状态（桥接的接口、对端实例和帧计数器），每次按 Enter 会刷新。

### 容器

Container 节点将一个 **Podman 容器**（rootful）作为 Lab 设备运行，例如 cEOS 或 cRPD 这类路由器镜像，或任何带有网络工具的 Linux 镜像。

选中容器节点时，**构建**标签页会显示容器专用字段：

| 字段                                 | 说明                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| **容器镜像**（Container image）      | 服务器上可用镜像的下拉列表（打开编辑器时读取自 `sudo podman images`）。                                |
| **支持状态**（Support status）       | 镜像在[容器支持库](#容器支持库)中时显示 `<名称> · 已支持`。                              |
| **运行参数**（Run parameters）       | 默认折叠；以只读方式显示节点启动时使用的 **命令**、**运行选项** 和 **控制台 Shell**。 |
| **以太网端口**（Ethernet ports）     | Ethernet 接口数量（`eth0`、`eth1`……）。                                                     |
| **接口地址**（Interface addressing） | 可选的每端口 IPv4 地址、前缀和网关。设置后，NLC 会在链路建立时在容器内配置该地址。          |

镜像和运行参数仅在容器**创建**时（即启动时）生效。停止容器会将其删除，因此每次重新启动都会用当前的镜像/命令从一个全新的容器开始。

#### 容器支持库

镜像需要哪个命令、哪些运行选项和哪个控制台 shell，并不是在编辑器中输入的，而是来自容器支持库 `backend/catalog/container.json`。条目按顺序尝试，第一个匹配的条目生效；没有任何条目匹配的镜像使用 `default` 条目（`sleep infinity`，shell 为 `/bin/sh`）。

```json
{
  "id": "frr",
  "label": "FRRouting",
  "match": ["frrouting/frr", "frr"],
  "command": ["/usr/lib/frr/watchfrr", "zebra", "staticd", "bgpd", "ospfd"],
  "runArgs": ["--privileged", "-v", "{{volume:config}}:/etc/frr"],
  "shell": "vtysh",
  "notes": "Shown under Run parameters."
}
```

| 字段      | 说明                                                                                       |
| --------- | ------------------------------------------------------------------------------------------ |
| `id`      | 小写标识符，须唯一。                                                                       |
| `label`   | 在编辑器中显示的名称。                                                                     |
| `match`   | 与仓库名（去掉 registry 和标签，如 `ios-xr/xrd-control-plane`）匹配的 glob 模式（支持 `*`，不区分大小写）。                                 |
| `command` | 在容器内运行的 argv，位于镜像之后。省略则使用镜像自身的 entrypoint。                       |
| `runArgs` | 放在镜像**之前**的 `podman run` 参数。关于 `{{volume:<name>}}` 参见[每节点卷](#每节点卷)。 |
| `shell`   | 控制台在容器内运行的程序。省略则为 `/bin/sh`。                                             |
| `notes`   | 可选备注，与运行参数一起显示。                                                             |

#### 每节点卷

停止的容器会被删除，其中写入的任何内容都会丢失。要在停止/启动之间保留某个目录，可在运行选项（`runArgs`）中用 `{{volume:<name>}}` 挂载一个每节点卷，例如 `-v {{volume:config}}:/etc/frr`。NLC 会将其替换为 `nlc-<node id>-<name>`。

卷的生命周期与节点的运行时状态相同，与 IOU nvram 一样，它在停止/启动之间保留，并**在卸载时删除**；查看器中的 **清空数据**（Wipe Data）会删除某个已停止节点的卷。

**设置。** 容器节点需要安装 Podman，并为 `podman` 以及负责连接其虚拟链路的辅助程序配置一次性的免密 sudo 规则——参见[安装指南](./07-installation.md#6-容器节点podman)。如果没有这些规则，容器节点启动时会报 sudo 错误。

## 连接节点

将鼠标悬停在节点上会显示其连接柄（边缘上的小圆点）。从连接柄拖动到另一个节点即可创建链路。NLC 会自动分配第一个可用的接口对。

- 如果两个节点都同时具有 **Ethernet** 和 **Serial** 接口，链路默认使用 Ethernet。
- **多链路**（Multilink）：在同样两个节点之间再次拖动，即可添加第二条（或第三条）链路。同一对节点之间的多条链路显示为一条捆绑的边，直到选中其中一条为止。

**容器链路。** 任何连接到容器节点的链路都会实现为一对直接的内核 `veth`（显示为青色的边），而不是通常的内部转发结构：

- **Container ↔ Container**——直接在两个容器之间创建一对 veth，无需其他操作。
- **Container ↔ IOU 设备**——将容器连接到一个 **IOULive86** 节点；其 **绑定接口** 会自动切换为 `auto`。容器链路使用桥接的 `e0/1`，IOU 侧链路使用其 `e0/0`，因此一个桥接恰好承载一条容器链路和一条 IOU 链路。容器不能直接连接到 IOU 节点；请改为通过 IOULive86 节点转接。

## 编辑节点

点击节点将其选中。左侧边栏的 **构建** 标签页会显示其属性：

| 字段                           | 说明                                                    |
| ------------------------------ | ------------------------------------------------------- |
| **名称**                       | 节点主机名标签，显示在画布上                            |
| **镜像**                       | 镜像文件名（IOU）或容器镜像                             |
| **绑定接口**                   | _（仅 IOULive86）_ 该节点桥接到的服务器物理网卡         |
| **接口**                       | Ethernet 和 Serial 的槽位/端口数量                      |
| **RAM / NVRAM**                | 节点启动时分配的内存，单位分别为 MB / KB（仅 IOU 节点） |
| **支持状态 / 运行参数 / 地址** | _（仅容器）_ 参见上文的[容器](#容器)                    |

### IOU 镜像与默认 RAM

编辑器通过**文件扩展名**区分两代 IOU 镜像：

| 扩展名 | 镜像                                                                           | 默认 RAM |
| ------ | ------------------------------------------------------------------------------ | -------- |
| `.bin` | 经典 IOU（IOS 15.x 及更早版本），例如 `I86BI_LINUX-AdvEnterpriseK9-M2_157.bin` | 256 MB   |
| `.iol` | IOL（IOS XE 17.x），例如 `I86BI_LINUX-adventerprisek9-ms-17-16-01a.iol`        | 512 MB   |

新节点使用其镜像的默认值。NVRAM 默认值均为 64 KB。

## 编辑链路

点击画布上的链路（边）将其选中。**构建** 标签页会显示：

- **接口类型**（Family）——Ethernet 或 Serial（如果两个节点都支持该类型，可在两者之间切换）
- **源 / 目标**（Source / Target）——两端各使用哪个接口；如有其他空闲端口，可通过下拉列表更改
- **描述**（Description）——可选的自由文本标注，显示在边上

## 删除元素

选中节点或边后按 **Delete** 键即可删除。删除节点时也会删除其所有相连的边。

## Lab 设置标签页

左侧边栏的 **Lab 设置**（Lab Settings）标签页提供：

- **显示接口标签**（Show interface labels）——切换画布中边上接口名称标签的显示
- **Lab ID**——该 Lab 的 UUID（只读）

## 保存

点击顶栏中的 **保存 Lab**（Save Lab）。对于新 Lab，这还会将 URL 重定向为包含 `?id=<labId>`，并启用 **查看**（View）按钮。

## 打开查看器

Lab 保存后，点击 **查看** 即可打开该 Lab 的拓扑查看器。在查看器中可以加载、启动节点并连接到节点。
