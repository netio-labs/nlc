# Lab 操作

NLC 通过加载、运行和卸载的生命周期来管理 Lab。所有控制都位于拓扑查看器的 **概览**（General）面板中。

## Lab 生命周期

### 加载

**加载** 为每个节点分配实例 ID，创建运行时目录，并写入描述拓扑连接的 `netmap` 文件。它**不会**启动任何节点进程。

- 加载按钮始终可用。你可以随时重新加载，包括在 Lab 已加载的情况下。
- 重新加载是幂等的：已有的实例 ID 分配和运行时文件（包括 IOU nvram 和 Virtual PC 的 `startup.cfg`）都会保留。
- 节点只在启动时读取 netmap，因此重新加载不会影响当前正在运行的节点。

### 卸载

**卸载** 会停止所有正在运行的节点，释放所有实例 ID 分配，停止所有活动的抓包会话，并删除该 Lab 的整个运行时目录（包括 IOU nvram 文件、Virtual PC 已保存的配置（`startup.cfg`）以及其他所有运行时状态）。下一次加载时，每个节点都将从干净状态启动。

> 仅当你打算完全丢弃当前运行状态时才使用卸载。

### 全部启动 / 全部停止

**全部启动** 同时启动 Lab 中的所有节点进程。**全部停止** 将它们全部停止。

也可以从节点详情面板中单独启动和停止各个节点。

## 应用拓扑变更

在拓扑编辑器中编辑 Lab 拓扑时，正在运行的节点进程不受影响，它们仍在使用上次加载时的 netmap。要在不丢失设备配置（IOU nvram、Virtual PC `startup.cfg`）的情况下应用变更：

1. **全部停止**——平稳地停止所有正在运行的节点。
2. **加载**——用更新后的拓扑重新写入 netmap。nvram 文件不会被改动。
3. **全部启动**——启动所有节点。每个节点在启动时读取新的 netmap。

这样可以保留 nvram 中存储的所有设备配置。如需在下一次卸载之后仍保留配置，请将其保存到该 Lab 的[配置](#保存与恢复设备配置)中。

## 节点控制

点击拓扑画布中的任意节点，即可在概览面板中打开其详情区域。

| 控制                            | 作用                                                       |
| ------------------------------- | ---------------------------------------------------------- |
| **启动**（Start）               | 启动该节点。                                               |
| **停止**（Stop）                | 停止该节点。                                               |
| **重置控制台**（Reset Console） | 向节点的控制台端口发送 telnet 重置，强制重新进行终端握手。 |
| **清空数据**（Wipe Data）       | _（仅容器，且节点已停止）_ 经确认后删除该节点的每节点卷。  |

## 运行中的 Lab

**Labs** 页面的左侧边栏中有一个 **运行中**（Active）视图。它显示当前至少有一个节点正在运行的所有 Lab，每一行显示 `running / total` 节点计数。

该列表按需获取——进入运行中视图时会实时探测当前状态。列表不会自动刷新；刷新页面即可更新。

## 复制 Lab

**Labs** 页面的每一行都有一个 **复制**（Duplicate）按钮。点击后会创建该 Lab 的完整副本，Lab、所有节点和所有链路都使用一组新的 UUID。复制出的 Lab 名称会追加 ` duplicated`。Lab 列表会自动刷新。

副本继承完整的拓扑和界面布局，以及已保存的[配置](#保存与恢复设备配置)。

## 保存与恢复设备配置

与运行时状态不同，已保存的配置在**卸载**后仍会保留，因此可以随时将 Lab 重置到某个已知配置。

IOU 设备（路由器和交换机）和 Virtual PC 参与此功能；IOULive86 和容器节点不参与。

### 保存

1. 先在每台设备上保存其配置：IOU 设备上执行 `write memory`，Virtual PC 上执行 `save`。NLC 读取的是设备已保存的配置，而不是其运行配置。
2. 点击 **保存**（Lab 必须已加载）并输入名称，例如 `preconfig1`。

重复使用某个名称时会先询问是否覆盖。保存时设备可以处于运行或停止状态。

### 替换设备配置

1. 停止要替换配置的设备。
2. 在下拉列表中按名称选择一个配置，点击 **替换** 并确认。与 IOS 的 `configure replace` 类似，每台已停止设备的启动配置会被配置中对应该设备的部分整体替换；正在运行的设备会被跳过并在报告中列出。
3. 启动设备：它们会以新配置启动。

### 查看、编辑与导出

- **查看** 会在右侧面板中打开所选配置：先是该配置与本 Lab 设备匹配情况的摘要，然后是每台设备的配置。
- **编辑**（Edit）切换到原始文本以进行修改；
- **下载**（Download）将其保存为 `.md` 文件；
- **删除**（Delete）将其移除。

已保存的配置是一个普通的 Markdown 文件——每台设备一个 `## <device name>` 小节。

## 控制台

点击 **控制台** 按钮，即可在新标签页中打开该 Lab 的浏览器终端。完整说明参见[控制台](./04-console.md)。
